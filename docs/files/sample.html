ユーザー登録 機能仕様書

1. 概要

本書はユーザー登録機能の仕様を定義する。

メールアドレスの重複チェック、パスワードの強度検証を行い、
登録完了後に確認メールを送信する。

表 1-2 機能情報
項目 内容
機能ID USER-001
ステータス 承認済
担当 チームA

2. エンティティ定義

2.1. User

システムのユーザーを表すエンティティ。

表 2.1-3 Userエンティティ
基本情報 検証
項目名 型 制約 説明
id int 自動採番 ユーザーID
name string 必須 最大100文字 ユーザー名
email string 必須 一意 email形式 メールアドレス
password_hash string ハッシュ化されたパスワード
created_at datetime 自動設定 作成日時
is_active boolean 初期値: false 有効フラグ

3. 操作仕様

3.1. register_user

新規ユーザーを登録する。

表 3.1-4 入出力パラメータ
区分 項目名 型 必須 説明
入力 name string ○ ユーザー名
email string ○ メールアドレス
password string ○ パスワード（8文字以上）
出力 user User － 登録されたユーザー
flowchart TD A[入力受付] --> B{バリデーション} B -- OK --> C[メール重複チェック] B -- NG --> D[ValidationError] C -- 重複なし --> E[ユーザー作成] C -- 重複あり --> F[EmailAlreadyExistsError] E --> G[確認メール送信] G --> H[完了]
図 1 登録処理フロー
※パスワードは8文字以上、英数字混合で設定してください。
※確認メールの有効期限は24時間です。
  1. ビジネスルール
    1. RULE-001: メールアドレスの重複チェック
    2. RULE-002: パスワード長のチェック（8文字以上）
    3. RULE-003: パスワード強度のチェック（英数字混合）
    4. RULE-004: ユーザー名の空チェック
表 3.1-5 ビジネスルール詳細
ルールID 条件 例外 メッセージ
RULE-001 同じメールアドレスが既に登録されている EmailAlreadyExistsError このメールアドレスは既に使用されています
RULE-002 パスワードが8文字未満 ValidationError パスワードは8文字以上で入力してください
RULE-003 パスワードに英字と数字の両方が含まれていない ValidationError パスワードは英字と数字を含めてください
RULE-004 ユーザー名が空 ValidationError ユーザー名を入力してください

3.2. activate_user

確認メールのリンクからユーザーをアクティベートする。

表 3.2-6 入出力パラメータ
区分 項目名 型 必須 説明
入力 user_id int ○ ユーザーID
token string ○ アクティベーショントークン
出力 success boolean － 成功フラグ
  • 成功時: is_activeをtrueに更新
  • トークン無効時: InvalidTokenErrorを返却
  • ユーザー不在時: UserNotFoundErrorを返却
